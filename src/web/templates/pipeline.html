📐 Three Distinct Architectural Execution Flows
Lightweight Query Routing

The system uses an intelligent QueryRouter to determine the exact processing pathway based on the query's intent. Unlike naive RAG systems that query vector stores on every interaction, our architecture only retrieves when semantic definitions are required, protecting analytical queries from context hallucination.

1. KNOWLEDGE Definitions / Metadata
Questions about column definitions, business rules, or dataset summaries.
User Query
↓
Query Router (Intent: KNOWLEDGE)
↓
Knowledge Retriever (TF-IDF Vector Store)
↓
Grounded Direct Answer (with Provenance)
⚡ Planner & Pandas Bypassed (Zero unnecessary computation)
2. ANALYTICAL Math / Aggregates / Trends
Questions requiring mathematical calculation, groupings, filters, or rankings.
User Query
↓
Query Router (Intent: ANALYTICAL)
↓
Existing Analysis Planner (JSON Plan)
↓
Plan Validator (Pydantic Schema Check)
↓
Pandas Engine & Plotly Visualizer
↓
LLM Result Explanation
⚡ RAG Retriever Bypassed (Zero retrieval noise or prompt clutter)
3. HYBRID Definitions + Math
Queries needing domain business context to inform the mathematical plan.
User Query
↓
Query Router (Intent: HYBRID)
↓
Knowledge Retriever (Top-K Chunks)
↓
Reference Context Injected (Trust Bound)
↓
Existing Analysis Planner & Validation
↓
Pandas Engine & Visualizer
↓
Grounded Explanation (with Provenance)
⚡ Dual Integration (Semantic context informs planner, Pandas calculates)
